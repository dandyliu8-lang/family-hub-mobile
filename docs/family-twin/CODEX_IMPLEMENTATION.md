## 1. 产品定位

这不是资讯推送工具，也不是一个通用聊天窗口，而是一个私有的、持续更新的家庭事实与行动系统：

采集 → 归属/核验 → 私有事实库 → 授权同步 → AI 分析 → 建议/待办 → 完成反馈 → 周期复盘。

一个家庭空间包含多个成员分身，每个成员有独立档案、时间线、资料、目标、权限与授权。家庭共享的是明确授权的信息，而不是默认公开每个人的全部记录。

领域完整目标：健康、成长学习、家庭日程与事务、财务。第一阶段以成员与健康/生活习惯闭环为主，复用已有财务模块，不重建金融账户系统。保留其他家属扩展能力，不自动创建或导入真实家属档案。

界面延续现有 Family Hub，石墨色、克制的精密工业风、移动优先；表单、来源、同步状态比大号标语更重要。入口：首页/家庭/记录/资料/AI/同步与权限；旧财务入口保持可用。

## 3. 数据采集与接入顺序

### M1 可真实实施的输入

- 按成员手动记录：身体测量、睡眠/运动、情绪自述、症状或皮肤观察、预约与待办；不将情绪评分推断为心理诊断。
- UTF-8 CSV/JSON 导入：上传 → 文件预检 → 列映射 → 成员/单位/日期预览 → 确认 → 幂等入库 → 错误行报告。
- 报告/照片资料：先支持私有保存、成员归属、采集日期、标签和删除；未经提取核验不生成结构化医疗事实。图片中的文字不是可信执行指令。
- 历史记录须区分当前事实、过去事实、示例与待确认事项；旧年级/年龄不能被永久硬编码。

### 后续接入，不能假装已连接

- Apple Health：首先提供 XML 导出文件导入适配；它是手动快照，不是自动同步。以后另做原生 iOS HealthKit 采集端，逐项申请权限并处理后台调度限制。网页/PWA 不能被当作原生 HealthKit 客户端。
- 血压计/体脂秤：具体型号及官方开放能力确认后接入；优先让兼容设备写入系统健康平台。不承诺任何品牌都能直连。
- 日历/文件：单独开发授权连接器，第一版只读；使用游标与增量同步、删除通知和重授权流程。ChatGPT 中已有的连接不等于自建应用已获得 OAuth 凭据。
- 医院报告、微信/银行卡账单等：优先使用用户主动导出的文件；没有授权的官方接口时明确为手动导入，不抓取账户密码、不模拟支付、不宣称自动直连。
- 语音：单独授权录音/转写；先生成待确认草稿，禁止直接把自然语言猜测写为事实。

## 4. 数据契约

建议核心实体：Household、Member、Membership、Device、SourceConnection、ConsentGrant、Observation、Attachment、FactVersion、Goal、CarePlan、Action、Review、SyncRun、Briefing、DeliveryAttempt、AuditEvent。

每条 Observation 至少包含：

- id、household_id、subject_member_id、recorded_by、schema_version；
- metric_code、value、unit、observed_at、recorded_at、timezone；
- source_type、source_id、external_record_id 或客户端幂等键、import_batch_id；
- verification_status（self_reported / source_imported / user_confirmed / disputed），这些表示来源核验状态，不保证测量准确；
- provenance（原始资料引用及页码/字段定位，适用时）；
- sensitivity、purpose、consent_version、supersedes_id、deleted_at。

关键规则：

1. 来源命名空间 + 成员 + 外部记录 ID 建唯一约束；同一来源键内容不一致报冲突，不静默覆盖。
2. 缺失值是 missing/null，不能填 0；未授权、没同步、设备未戴与真实 0 必须区分。
3. 单位转换保留原单位与转换规则；测量时间与上传时间分开。血压作为同一次测量的成对数值记录。
4. 用户更正创建新版本；旧事实保留审计但不能继续进入当前趋势。删除/撤销须联动派生数据、检索索引、待发简报和同步墓碑。
5. 年龄由已确认出生日期计算；年级使用生效区间。无生日时使用年龄段，不倒推具体出生日期。
6. AI 推断、目标值、真实测量分别存放。AI 只能提出事实更正草稿，不能无提示更改记录。
7. 附件默认私有，访问需鉴权与短时授权；不要将文件名或人物信息写进公开 URL。

## 5. 安全与授权：保留端到端加密，不伪称云端无明文

现有私密库中，云端持有密文而没有解密密钥。服务端 AI 不能凭空分析这些密文。

采用两个明确隔离的区域：

A. 私密原始库：保持现有端到端加密设计；原始报告、详细交易、敏感笔记默认留在这里。
B. 授权分析区：成员明确选择字段、用途、时间范围、模型供应商、保留周期后，客户端生成最小化摘要。摘要在服务器存储时加密，但被授权的服务和模型推理时能接触必要明文，不能称其仍对这些服务端到端加密。

授权默认关闭。夫妻各自同意个人数据共享；家庭管理员身份不自动获得所有成员健康/财务读取权限。未成年成员采用监护权限并提供适龄解释，避免隐蔽持续监控和心理标签。

授权撤销必须立即阻止后续检索、任务和模型调用；清除可控缓存/派生数据；对备份和供应商已接收数据的删除边界如实说明，不能承诺不可验证的彻底抹除。

M1 不向任何模型传输数据；只实现授权界面与约束。M2 接入模型前必须完成服务端身份校验、按对象鉴权、配额、传输清单、供应商数据处理审查和明确确认。

生产密钥只进入服务器密钥管理/环境配置，不进入浏览器、Git 或 Codex 提示词。日志脱敏；备份加密；提供导出、恢复演练、账号撤销和访问审计。保护数据与密钥分离，测试环境禁用真实数据。新增数据域不得直接继承家庭财务的共享密钥权限。

## 6. 同步要求

页面同时展示：最近源数据时间、最近成功同步时间、数据覆盖率、授权状态、待同步条数、冲突和错误；“已连接”不是“已同步”。

实现离线队列、重连补传、幂等写入、重试退避、分页游标、冲突保留和人工解决。不得以最后写入胜出静默覆盖健康数据。

跨设备加密同步是一条链，第三方数据源同步是另一条链，AI 摘要授权又是第三条链。分别记录状态与失败原因，不能合并成一个绿色圆点。

新数据域使用版本化信封；复用现有同步机制前写兼容性/迁移测试；旧客户端遇到未知版本应明确拒绝而不是擦除字段。成员撤权/设备撤销后轮换访问权限并防止继续读取新数据。删除在离线设备重连后不得复活。

## 7. AI 大脑

第一版只做一个有状态编排器，不构建多 Agent 集群：

1. 读取本次任务的有效授权和数据新鲜度。
2. 用程序计算趋势与覆盖率；模型不自行算均值或补齐缺失记录。
3. 按权限检索个人事实、医生明确给出的目标与资料；公共知识检索使用去标识的主题，不把姓名、学校或原始病历放进搜索词。
4. 医疗知识只从受控官方/专业学会来源取证；发布日、更新日、检索日、指南/单项研究/科普类型分别标记；美国建议与本地诊疗适用性分开。
5. 输出结构化建议：事实、证据、解释、不确定性、建议动作、需确认项。
6. 生成行动草稿；药物调整、预约、对外分享、购买、财务操作不可自动执行。
7. 保存模型版本、证据 ID、分析使用的事实版本、授权快照、成本、运行状态；敏感正文不写普通日志。
8. 新增记录或授权变化后，标记旧分析是否过期。

模型不可用时只呈现真实记录和明确标为“规则提示”的预设内容，不伪装为 AI 输出。医学阈值须来自核验指南或医生计划、可版本化，不在 UI/模型提示中随意硬编码。产品不是诊断或急救监控服务。

## 8. 调度、推送与复盘

家庭时区可配置，默认部署时明确选择；服务端持久调度，不依赖网页常开、电脑不休眠或 Codex 会话存活。

默认计划：每日 08:00 早报；周一至周六 20:30 晚报；周日 20:30 周复盘替代晚报。时区按 Asia/Shanghai 配置的测试需要覆盖服务器 UTC 差异。

早报关注今天的建议，晚报关注用户实际反馈；没有反馈不能宣布完成。周报至少展示数据覆盖率、真实变化、未完成/未知事项、下周有限目标和依据。

任务必须持久化 job_key、幂等状态、重试次数、最后错误、结果 ID。推送采用 outbox；状态分为 planned / generating / saved / provider_accepted / delivery_confirmed（仅提供商支持时）/ read（应用实测）/ failed。不能把“服务商已接收”说成“用户已读”。断网重试不重复生成；漏跑补偿有时限，避免集中轰炸。

推送锁屏内容默认仅“家庭简报已更新”，不包含血压、病名或孩子隐私。站内收件箱是可追溯的结果入口。外部通知未授权时显示明确提示，并保留站内结果。PDF 为私有简报附件，不暴露为永久公开下载地址。

迁移成功前保留已有 ChatGPT 提醒；新系统完成调度与通知实测后再由用户决定停用旧任务，避免重复和漏发。本轮不改旧任务。

## 9. 实施里程碑

### M0：现状与兼容性

盘点默认分支及正在开发分支；运行已有测试（没有则补最小基线）；确认现有数据结构、密码派生、导出/恢复与同步协议。输出复用清单、缺口及最小迁移方案。

### M1：真实数据闭环（第一轮交付）

家庭/成员/权限模型；手动录入和 CSV 导入预览；来源与版本时间线；附件私有元数据；授权面板（不调用外部模型）；两个独立浏览器存储上下文的同步测试；空态/缺失/错误显示；保留已有财务回归。

先完成本地与测试后端的可运行闭环。两上下文模拟不等于真实 iPhone/电脑验收，必须分开报告。尚未部署后端时，UI 只能显示“未配置”，不能出现假成功。

### M2：AI 与有证据的关怀

接入服务端模型适配器、授权摘要、事实检索、官方来源记录、结构化输出和人工确认；模型供应商/模型 ID 环境配置，不硬编码所谓最新型号。无需模型 Key 的测试使用明确标识的 mock；真实 Key 由用户在合适渠道配置后再测试。

### M3：长期运行

独立 API/worker + PostgreSQL（事实与任务）+ 私有对象存储 + 可配置模型适配器。优先模块化单体，先不要 Kubernetes 或复杂多 Agent。复用现有 PWA，不把第三方 AI 编码工作区当生产服务器。

上线前完成登录、按成员鉴权、备份恢复、服务重启后的任务恢复、晨晚报/周报去重、通知权限状态和一次端到端投递。实际域名、云资源、费用和生产写权限须单独授权，不复用其他业务系统的数据库、身份、密钥或生产数据。

### M4：自动采集扩展

Apple Health XML 适配 → 原生 HealthKit 同步；经授权的日历/文件连接器；按具体设备支持情况接入测量设备；成长学习/家庭事务/财务的跨域建议。每个连接器必须独立验收，不能用演示卡片冒充已接入。

## 10. 必须通过的验收场景

1. 没有个人数据时不显示示例数值为真实状态。
2. 用户录入一条记录、刷新/锁定解锁后仍在，且按成员正确归属。
3. 同一 CSV 导入两次不增加重复记录。
4. 同来源 ID 不同值产生可见冲突，不静默覆盖。
5. 错误单位、无时区日期和跨成员导入都需纠正或确认。
6. 更正有历史，当前趋势只使用有效版本。
7. 无数据日保持缺失，不当作 0 或习惯未完成。
8. 两浏览器上下文并发编辑都保留，不损失旧财务数据。
9. 撤销授权/移除设备后不能获取新数据，权限绕过测试失败。
10. 新旧客户端协议不兼容时不丢字段。
11. 未授权成员的数据不能进入检索、模型请求、PDF、日志或推送。
12. AI 解释能返回具体事实版本和官方来源，不能编造新闻日期。
13. 上游附件/网页的提示注入不能改变工具权限或触发外发。
14. 模型超时有明确降级；没有 Key 不显示真实 AI 已连接。
15. 早晚报与周报按时区生成；周日不重复晚报。
16. 任务重试不会产生重复简报/重复通知。
17. 服务重启后任务状态可恢复，漏跑可追踪。
18. 关闭通知权限后界面明确表示未启用；站内结果仍可访问。
19. 无完成反馈时周报标“未知”，不编造坚持率和健康改善。
20. 删除记录后检索/趋势/待发报告失效，离线重连不会复活。
21. 加密导出恢复可复现，配对/密钥不出现在普通导出或日志。
22. 生产上线前测试 HTTPS、身份鉴别、成员隔离、跨域限制与备份恢复。
